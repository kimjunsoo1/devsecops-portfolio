# ADR 0002 — NAT 게이트웨이를 쓰지 않는다

- 상태: 채택
- 날짜: 2026-09-03

## 맥락

교과서적인 3계층 VPC는 애플리케이션을 프라이빗 서브넷에 두고,
아웃바운드 인터넷 접근(컨테이너 이미지 pull, 패키지 설치)을 NAT 게이트웨이로 처리한다.

서울 리전 NAT 게이트웨이는 시간당 요금만으로 월 약 $35이고 데이터 처리 요금이 별도로 붙는다.
이 프로젝트의 월 예산 상한이 $50 수준이므로, NAT 하나가 예산의 70%를 쓴다.

## 결정

Fargate 태스크를 퍼블릭 서브넷에 배치하고 퍼블릭 IP를 할당한다.
대신 다음으로 노출면을 좁힌다.

- 보안그룹 인바운드는 ALB 보안그룹에서 오는 트래픽만 허용. 0.0.0.0/0 인바운드 없음.
- 태스크 IAM 역할은 필요한 액션만.
- 애플리케이션은 non-root, 읽기 전용 루트 파일시스템으로 실행.

## 대안

- **VPC 인터페이스 엔드포인트** (ECR api / ECR dkr / CloudWatch Logs + S3 게이트웨이):
  NAT 없이 프라이빗 서브넷을 유지할 수 있지만 인터페이스 엔드포인트가 개당 월 약 $7.3,
  세 개면 월 $22로 여전히 비싸다. 트래픽이 커지면 NAT보다 유리해지는 시점이 오지만 이 규모에서는 아니다.
- **NAT 인스턴스(t4g.nano)**: 월 $3 수준으로 싸지만 직접 운영해야 하고 단일 장애점이 된다.

## 결과

- 월 $35을 아꼈고, 그 예산을 WAF와 Fargate 상시 운영에 썼다.
- 프라이빗 서브넷 대비 노출면이 넓어졌음을 인지하고 있으며, 보안그룹과 IAM으로 보상한다.
- 트래픽이 커지거나 실무 환경이라면 인터페이스 엔드포인트로 이전하는 것이 다음 선택지다.
