# ADR 0006 — SAST 를 Semgrep 과 CodeQL 로 나눈다

- 상태: 채택
- 날짜: 2026-10-13

## 맥락

3주차 모듈 4 에서 게이트를 상대로 침투 테스트를 했다. 의도적으로 취약한
코드를 PR 로 올려 각 게이트가 막는지 확인하는 작업이다.

GitHub 푸시 보호, gitleaks, Trivy 는 전부 막았다. **Semgrep 만 통과시켰다.**

처음에는 심각도 기준(`ERROR` 등급만 차단) 문제로 봤다. 그래서 기준을
`WARNING` 까지 내리려 했는데, 확인해 보니 원인이 달랐다.

`p/javascript` 룰셋 68개를 그 파일 하나에만 돌려도 발견 사항이 0건이었다.
출력 하단에 이유가 있었다.

```
💎 Missed out on 218 pro rules since you aren't logged in!
```

Semgrep OSS 의 커뮤니티 룰셋은 IaC·워크플로·시크릿에는 강하지만
애플리케이션 코드 취약점 룰 상당수가 Pro 로 이동했다. Pro 는 Semgrep 계정과
CI 에 저장할 토큰을 요구한다.

**기준이 느슨한 게 아니라 그 언어를 보고 있지 않았다.** 심각도만 낮췄다면
노이즈가 늘었을 뿐 이 구멍은 그대로 남았을 것이다.

## 결정

도구를 역할별로 나눈다.

| 도구 | 담당 |
|---|---|
| Semgrep | Terraform, GitHub Actions, 시크릿 패턴 |
| CodeQL | JavaScript / TypeScript 애플리케이션 코드 |
| Trivy | 의존성 CVE, IaC 오구성 |
| gitleaks | 커밋 히스토리 시크릿 |

CodeQL 을 고른 이유는 셋이다. 퍼블릭 리포지토리에서 무료이고,
CI 에 저장할 토큰이 없으며(2주차의 "장기 자격증명 없음" 원칙과 일치),
데이터플로 분석을 한다.

Semgrep 은 유지한다. 액션 태그 고정 지적 14건을 잡아낸 것이 이 도구의
값어치를 보여준다. 못하는 영역이 있다고 버릴 이유는 없다.

Semgrep 게이트의 `ERROR` 기준도 그대로 둔다. 구멍의 원인이 기준이 아니었으므로
낮출 근거가 없다.

## 시험 픽스처의 한계도 함께 기록한다

침투 테스트에 쓴 `vulnerable-app.js` 는 `eval()` 과 `child_process.exec()` 를
호출하는 함수를 export 만 했고, 그 함수를 부르는 **진입점이 없었다.**

데이터플로 기반 분석기는 "사용자 입력(소스) → 위험한 함수(싱크)"의 경로를
찾는다. 진입점이 없으면 소스가 없고, 경로가 성립하지 않는다.
CodeQL 도 같은 이유로 이 파일을 그냥 지나갈 가능성이 높다.

**SAST 시험 픽스처는 실제 진입점을 포함해야 한다.**
5주차에 컨테이너 API 를 만들 때 HTTP 핸들러를 가진 형태로 다시 작성한다.

## 결과

- 애플리케이션 코드에 대한 커버리지가 생겼다. 5주차 API 가 들어올 때
  이미 자리를 잡고 있다.
- 도구가 하나 늘어 CI 시간이 길어진다(CodeQL 초기 분석 3~5분).
  PR 당 비용이지만 퍼블릭 리포지토리라 요금은 없다.
- 침투 테스트를 하지 않았다면 5주차에 API 를 올리고 나서야,
  혹은 영영 몰랐을 구멍이다.
